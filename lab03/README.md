# Лабораторная работа № 3. Многофайловая сборка

Проект выводит аргументы командной строки с порядковыми номерами. При запуске без аргументов программа выводит справку и версию в stderr. В проекте три единицы трансляции и общий заголовок.

| Символ | Тип | Где определён | Где используется |
| --- | --- | --- | --- |
| `main` | Функция | `main.c` | Код запуска программы |
| `print_line` | Функция | `output.c` | `main.c` |
| `print_usage` | Функция | `output.c` | `main.c` |
| `line_number` | Глобальная переменная с нулевой инициализацией | `counter.c` | `main.c`, `output.c` |

Makefile формирует три варианта программы. В первом компоновщик получает объектные файлы напрямую, во втором извлекает нужные модули из архива `liblab03.a`, в третьем записывает динамическую зависимость от `liblab03.so.1`. Цель `full-static` дополнительно требует статический вариант libc.

Для динамической библиотеки `output.c` и `counter.c` компилируются с `-fPIC`. При запуске из каталога разработки цель `run-shared` передаёт путь к библиотеке через `LD_LIBRARY_PATH`. В RPM исполняемые файлы устанавливаются через макрос `%_bindir`, библиотека – через `%_libdir`. Этот макрос учитывает выбор каталога библиотек для архитектуры стенда.

Сценарий `bash check/check-lab03.sh` сохраняет диагностику и результаты команд в `logs/`, выводит статус каждой проверки и завершает работу с ненулевым кодом при наличии ошибок. Настройка проверки пакета описана в `env/README.md`.

Проверки проведены на ALT Workstation 11.1 (p11, x86_64), GCC 13.2.1 и GNU make 4.4. Подробности сохранены в `logs/`.

В таблице `nm` символы `main`, `print_line` и `print_usage` имеют тип T, `line_number` имеет тип B. Оставшиеся после сопоставления модулей внешние ссылки `puts`, `stderr`, `__fprintf_chk` и `__printf_chk` разрешила glibc.

Определение одной функции в общем заголовке вызвало `multiple definition` при компоновке. Сборка разделяемой библиотеки из объектов без `-fPIC` завершилась ошибкой `R_X86_64_32`. Запуск программы без пути к библиотеке завершился с кодом 127. Указание пути через `LD_LIBRARY_PATH` позволило загрузить библиотеку и получить эталонный вывод.

Для полностью статической сборки архивы из RPM `glibc-devel-static` извлечены в домашний каталог и подключены через `STATIC_LDFLAGS`. Обычный файл имеет размер 22 888 байт и 36 записей `nm`. Полностью статический файл имеет размер около 3,05 МБ и 1930 записей `nm`.

В hasher собраны основной RPM и подпакет отладочной информации. После установки обе команды запускаются по имени и дают одинаковый вывод без `LD_LIBRARY_PATH`. Библиотека установлена в `/usr/lib64`. В выводе `ldd` используется `/lib64`, который в окружении сборки указывает на `/usr/lib64`. Динамическая запись NEEDED присутствует только у `lab03-shared`. RPM объявляет библиотеку в Provides, а собственная библиотека пакета отсутствует в списке внешних Requires.
