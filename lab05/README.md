# Лабораторная работа № 5. Отладка

Стенд: ALT Workstation 11.1, p11, x86_64. Генератор арифметической прогрессии поддерживает справку и три режима аргументов. `file` и `readelf` подтвердили объект REL, библиотеку DYN и исполняемый PIE типа DYN. В заголовке PIE 13 программных и 39 секционных записей, точка входа 0x10a0 соответствует _start. Идентификаторы сборки из двух утилит совпали. Отладочные разделы перечислены в журнале.

| Сборка | Размер, байт | Наблюдение |
| --- | ---: | --- |
| Обычная | 18888 | Для main нет информации о строках |
| -g -O0 | 21800 | Доступен исходный текст |
| -g -O2 | 24104 | Часть локальных переменных имеет статус optimized out |

После перемещения файла и временного удаления исходника из каталога компиляции GDB сообщил, что progression.c отсутствует. После возврата исходника список строк снова доступен. Путь к исходнику хранится в DWARF.

В упражнении поиска дефекта использована ошибка вычисления без повреждения памяти. Точки останова установлены в source_value и transform, стек показал transform, run и main. Коэффициент 3 давал 18, после исправления на 2 результат 12. Опыт с записью через неинициализированный указатель и проверка повторного использования адреса стека не выполнялись.

После strip размер снизился до 14936 байт. Отдельный файл, созданный objcopy, подключён через .gnu_debuglink. Пакет glibc-core-debuginfo из компонента debuginfo установлен в hasher. При передаче извлечённых символов локальному GDB найдена функция __libc_start_call_main. Адрес публичного сервера не ответил. Для проверки сетевой загрузки использован локальный HTTP-источник по пути build-id, файл попал в кэш debuginfod. Devel-пакет нужен для компиляции и компоновки, debuginfo содержит сведения для отладки готового файла.

Пакетные сценарии GDB печатают четыре помеченные строки в трёх прогонах. Диагностика и стек хранятся отдельно от эталона. Локальная команда из .gdbinit появилась после разрешения конкретного файла через safe-path.

В hasher без /proc GDB не смог вставить точку останова. Условия монтирования и подготовка описаны в `env/`. Удалённая отладка подтверждена в пределах гостевой системы по loopback. Сервер запускал только лабораторный процесс. При ptrace_scope=1 подключение к отдельно запущенному процессу sleep завершилось EPERM. Настройки ядра не изменялись.
