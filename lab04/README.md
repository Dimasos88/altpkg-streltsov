# Лабораторная работа № 4. Обработка текстов и сценарии

Стенд: ALT Workstation 11.1, p11, x86_64, Bash 5.2, Git 2.50.1. В `sources/` находятся сценарий списка задач и демонстрация очистки временного файла. В `specs/` сохранены исходный spec-файл и правила экспорта.

| Команда | Класс | Пакет |
| --- | --- | --- |
| `cd` | Встроенная | Bash |
| `printf` | Встроенная, также доступна внешняя | coreutils для внешней |
| `sort` | Внешняя | coreutils |
| `rpm` | Внешняя | rpm |
| `lab04ls` | Псевдоним | – |

| Подстановка для `v=one:two:three` | Результат |
| --- | --- |
| `${v#*:}` | `two:three` |
| `${v##*:}` | `three` |
| `${v%:*}` | `one:two` |
| `${v%%:*}` | `one` |

До export переменная в дочернем Bash пуста. После export он получает копию значения `parent`. Изменение значения в дочерней оболочке не меняет состояние родительской. При `>file 2>&1` оба дескриптора направлены в файл. При `2>&1 >file` stderr дублирует stdout до его перенаправления и остаётся на исходном потоке. Оператор `>` без номера перенаправляет дескриптор 1.

Временные объекты создаются с правами 600 для файла и 700 для каталога. Проверены штатный выход, ошибка, SIGINT и SIGTERM. В каждом случае EXIT-обработчик удалил файл. Проверка `mktemp -u` вернула имя без создания файла, а шаблон с двумя `X` отвергнут.

Вывод `ps` разделён на таблицы с PID, именем команды и UID. Для реальных PID оба входа сортируются в C. На контрольных ключах с разным регистром сортировка C и объединение в ru_RU.utf8 дали диагностику порядка. Когда обе утилиты использовали C, объединение прошло. `hexdump`, `od` и `xxd` вывели байты `41 4c 54 0a`. Пакеты-владельцы – util-linux, coreutils и xxd. При перенаправлении в исходный файл оболочка обрезает его до обработки, а `sponge` ждёт завершения чтения. `ts` добавляет метки времени.

Сценарий `lab04-todo` хранит данные в TSV и поддерживает меню dialog и команды add, list и done. Массив Bash и кавычки сохраняют пробелы в аргументах. Выбор dialog считывается из отдельного временного файла. Проверены первый запуск, сохранение трёх записей, изменение статуса и меню в псевдотерминале.

Прямой RPM собран в hasher из SRPM с одним файловым источником. Команды awk, dialog, flock, mkdir, mktemp, mv, rm и touch обнаружены обработчиком find-requires. В метаданных появились /bin/bash, coreutils, dialog, gawk и util-linux. Установка без dialog отклонена по зависимости. После его добавления пакет установлен и запущен по имени.

[GEAR-репозиторий](https://github.com/Dimasos88/lab04-todo) содержит ветви master и srpms, теги 1.0-alt1 и 1.1-alt1. Правило `copy: *.sh` экспортирует сценарий как отдельный Source0. Версия 1.1 добавляет команду count, сохраняется в коммите, сформированном gear-commit из %changelog.

Команды проверки и требования к окружению указаны в `env/README.md`. Фактические результаты сохранены в `logs/`.
