# Лабораторная работа № 7. Трассировка вызовов

Работа выполнена на ALT Workstation 11.1, p11, x86_64. Сценарий `check/check-lab07.sh` запускает эксперименты и фиксирует результаты в `logs/`.

Протокол strace по умолчанию направляется в stderr. Сравнение stdout и stderr выполнено на /bin/true. В опыте с ls -l больше событий, поскольку программа читает каталог, загружает библиотеки, запрашивает метаданные и форматирует данные. Сводка по времени, количеству и ошибкам сохранена в `logs/ls.stats`. Последовательность фильтров: группа %file, openat, два заданных пути, успешный статус. Флаг -y вносит путь рядом с дескриптором, -s меняет предел длины строки. Команда с env -i передаёт контролируемый набор переменных.

Отслеживание потомков добавляет PID к каждой строке протокола -fo и показывает запуск программ через execve. Родитель получает SIGCHLD при завершении потомков. При -k отладочный файл показывает имена функций, а в очищенном исполняемом файле виден адрес смещения.

На библиотечном уровне ltrace показал strlen, strcmp, open и read. Первые две функции выполняются в пользовательском пространстве, вызовы open и read соответствуют openat и read на системном уровне. Статический файл не имеет динамических импортов rand и printf. При ptrace_scope=1 strace и GDB не подключились к отдельному процессу sleep, запущенному для лабораторной. Содержимое available_tracers недоступно непривилегированному пользователю.

В учебной программе rand разрешается через libc. При запуске с локальным libconstant.so символ с тем же именем становится доступен раньше libc, и вместо случайных значений программа печатает 42. Механизм повышает риск, если непроверенный объект попадает в окружение запуска. Опыт ограничен лабораторным процессом.

| Ситуация | Код | Состояние |
| --- | ---: | --- |
| Не заданы параметры | 2 | Файловые операции не начаты |
| Исходника нет | 3 | Цель не создана |
| Исходник недоступен для чтения | 4 | Исходник сохранён |
| Исходник и цель указывают на один файл | 5 | Файл сохранён |
| В целевом каталоге нет права записи | 6 | Исходник сохранён |
| Существующая цель заменена | 0 | Данные совпали, исходник удалён |

Внедрение EIO в read, ENOSPC в write и EACCES в rename дало коды 7, 8 и 10. В каждом опыте исходник сохранён и целевой файл не появился. Первое чтение загрузчика предшествовало чтению данных программы. Подмена результата чтения и доставка сигнала проверены в тестах обработки сигналов. Учебный libguard.so отказал в удалении файла с контрольным именем и пропустил обычное имя.
